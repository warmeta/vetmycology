<task type="auto">
  <name>Task 2: Create Breadcrumb.astro component</name>
  <files>src/components/Breadcrumb.astro</files>
  <action>
Create `src/components/Breadcrumb.astro`. This component renders two outputs: a visible `<nav>` element in its normal template body, and a `<script type="application/ld+json">` tag with `slot="head"` that ContentPage will forward to BaseLayout's `<slot name="head" />`.

**Component Props interface:**
```typescript
interface Props {
  breadcrumbParent: string;  // Spanish key, e.g. "Patologías" — must match parentMap
  title: string;             // current page title (leaf label)
  lang: 'es' | 'en';
}
```

**parentMap** — static object literal keyed by Spanish label. Each entry has `esPath`, `enPath`, and `label` (object with `es` and `en` keys):
- `'Micología'` → esPath `/micologia/generalidades/`, enPath `/en/micologia/generalidades/`, label es `Micología` / en `Mycology`
- `'Patologías'` → esPath `/patologias/levaduras/`, enPath `/en/patologias/levaduras/`, label es `Patologías` / en `Pathologies`
- `'Investigación'` → esPath `/investigacion/articulos-congresos/`, enPath `/en/investigacion/articulos-congresos/`, label es `Investigación` / en `Research`
- `'Laboratorio'` → esPath `/laboratorio/`, enPath `/en/laboratorio/`, label es `Laboratorio` / en `Laboratory`
- `'Recursos'` → esPath `/recursos/archivo-imagenes/`, enPath `/en/recursos/archivo-imagenes/`, label es `Recursos` / en `Resources`

**Derivations in frontmatter:**
- `const parent = parentMap[breadcrumbParent]` — look up parent entry
- `const parentHref = lang === 'en' ? parent?.enPath : parent?.esPath` — locale-appropriate href
- `const parentLabel = parent?.label[lang] ?? breadcrumbParent` — locale-appropriate label; fallback to raw key
- `const homeHref = lang === 'en' ? '/en/' : '/'`
- `const homeLabel = t('breadcrumb.home')` — "Inicio" or "Home"
- `const siteOrigin = Astro.site?.origin ?? 'https://micologiaveterinaria.ulpgc.es'`

**JSON-LD object** — build as a JavaScript object literal, then render with `set:html={JSON.stringify(jsonLd)}`:
```javascript
const jsonLd = {
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": homeLabel, "item": `${siteOrigin}${homeHref}` },
    { "@type": "ListItem", "position": 2, "name": parentLabel, "item": `${siteOrigin}${parentHref}` },
    { "@type": "ListItem", "position": 3, "name": title }
  ]
};
```

Note: third ListItem has no `item` property — Google's spec allows omitting `item` on the leaf (current page). Do NOT use string concatenation to build JSON.

**CRITICAL — use `set:html` for the JSON-LD script tag, not template expression:**
```astro
<script type="application/ld+json" set:html={JSON.stringify(jsonLd)} slot="head" />
```
Using `{JSON.stringify(jsonLd)}` without `set:html` causes Astro to HTML-escape the JSON, making it invalid. Always use `set:html` for raw JSON output in script tags.

The `slot="head"` attribute on this script tag causes Astro to route it into ContentPage's `<slot name="head" slot="head" />`, which ContentPage forwards to BaseLayout's `<slot name="head" />`.

**Visible breadcrumb HTML** (after the script tag, in normal template body):
```astro
<nav aria-label={t('breadcrumb.aria-label')} class="breadcrumb">
  <ol>
    <li><a href={homeHref}>{homeLabel}</a></li>
    <li aria-hidden="true" class="sep">›</li>
    <li><a href={parentHref}>{parentLabel}</a></li>
    <li aria-hidden="true" class="sep">›</li>
    <li><span aria-current="page">{title}</span></li>
  </ol>
</nav>
```

Key ARIA points (per D-03 and WAI-ARIA APG breadcrumb pattern):
- Container must be `<nav>` (landmark), not `<div>`
- List must be `<ol>` (ordered — position conveys meaning)
- Separator `<li>` elements get `aria-hidden="true"` so screen readers don't announce the `›` character
- Current page item uses `<span aria-current="page">` — NOT a link (D-03)
- `aria-label` is translated via `t('breadcrumb.aria-label')`

**CSS** — scoped `<style>` block using existing CSS Custom Properties tokens from global.css:
- `.breadcrumb`: font-family var(--font-body), font-size var(--font-size-sm), color var(--color-text), opacity 0.65, margin-bottom var(--space-sm)
- `.breadcrumb ol`: list-style none, margin 0, padding 0, display flex, flex-wrap wrap, align-items center, gap 0
- `.breadcrumb li`: display inline
- `.breadcrumb .sep`: margin 0 var(--space-xs)
- `.breadcrumb a`: color inherit, text-decoration none
- `.breadcrumb a:hover`: text-decoration underline
- `.breadcrumb [aria-current="page"]`: font-weight 400 (same weight as rest — current page is not bolded; visual distinction is provided by absence of underline)

Do not add `--color-accent` to the breadcrumb link color — the muted `color: inherit` with 0.65 opacity is intentional per the "subordinate to the page title" styling decision in CONTEXT.md.
