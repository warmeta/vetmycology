Create the directory `.github/workflows/` and write the deploy workflow.

The workflow must satisfy all of the following requirements exactly — do not deviate:

- `name: Deploy to ULPGC`
- `on: push: branches: [main]` — only deploys from main, not from PRs (prevents fork injection per D-08)
- `concurrency: group: production-deploy` + `cancel-in-progress: true` — serializes deploys to prevent server corruption (Pitfall 7)
- Job: `build-and-deploy` on `ubuntu-latest`
- Step 1: `actions/checkout@v4`
- Step 2: `actions/setup-node@v4` with `node-version: '22'` and `cache: 'npm'` — must be `'22'` not `'20'` because `package.json` declares `engines: { node: ">=22.12.0" }` (Pitfall 8)
- Step 3: `run: npm ci` (uses committed package-lock.json)
- Step 4: `run: npm run build`
- Step 5: `SamKirkland/FTP-Deploy-Action@v4.4.0` with:
  - `server: ${{ secrets.FTP_SERVER }}`
  - `username: ${{ secrets.FTP_USERNAME }}`
  - `password: ${{ secrets.FTP_PASSWORD }}`
  - `local-dir: ./dist/` — trailing slash mandatory (uploads contents of dist/, not dist/ itself — Pitfall 2)
  - `server-dir: /httpdocs/` — trailing slash mandatory
  - `protocol: ftps`
  - `security: loose` — required because the FTP target is a bare IP (217.116.2.102); the server cert is issued to the hostname, not the IP, so TLS hostname validation fails without this flag (Pitfall 3)

Do NOT hardcode any FTP credentials in the YAML. All three FTP values must reference secrets.

Add a comment block at the top of the file explaining the `security: loose` flag and noting that the three GitHub Secrets (FTP_SERVER, FTP_USERNAME, FTP_PASSWORD) must be created in the repository settings before the workflow can succeed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub → ULPGC server | FTP credentials cross this boundary; must never appear in repo |
| PR from fork → main | Fork workflows must not trigger deploy; `on: push: branches: [main]` prevents this |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | FTP credentials in deploy.yml | mitigate | All three values stored as GitHub Actions Secrets (`${{ secrets.* }}`); GitHub masks secrets in logs |
| T-04-02 | Elevation of Privilege | Fork PR triggers deploy to live server | mitigate | `on: push: branches: [main]` — only commits merged to main trigger deploy; fork PRs never have write access to main |
| T-04-03 | Tampering | Concurrent deploys corrupting server file state | mitigate | `concurrency: group: production-deploy, cancel-in-progress: true` serializes deployments |
| T-04-04 | Tampering | npm/pip/cargo installs | accept | No new npm packages installed in this plan; only GitHub Action referenced by tag |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | Zero new npm installs in this plan; SamKirkland/FTP-Deploy-Action is a GitHub Action tag reference, not an npm package |
</threat_model>
