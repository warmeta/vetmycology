<objective>
Create the GitHub Actions deploy pipeline and document the one-time Plesk Git setup.

**Deploy flow (Option A — Plesk Git via GitHub):**
1. Developer pushes to `main`
2. GitHub Actions: checkout → Node 22 → `npm ci` → `npm run build`
3. GitHub Actions: assembles a `deploy-staging/` directory:
   - `deploy-staging/public/` — all `dist/` contents (the built site)
   - `deploy-staging/.htaccess` — denies `/.git/` access at the `/httpdocs/` level
4. `JamesIves/github-pages-deploy-action@v4` force-pushes `deploy-staging/` contents to the `prod` branch
5. GitHub fires a webhook to Plesk
6. Plesk Git extension pulls the `prod` branch into `/httpdocs/`
7. `/httpdocs/public/` is the Plesk document root — serves the live site

**Why this structure:**
- `/httpdocs/` is where Plesk Git clones — it creates `/httpdocs/.git/` there
- Document root is `/httpdocs/public/` — the actual site files, never the `.git/` directory
- The `.htaccess` at `/httpdocs/.htaccess` adds a second layer blocking `/.git/` even if misconfigured
- No FTP credentials, no server secrets — only `GITHUB_TOKEN` (automatic in Actions)

**Human-required steps (one-time Plesk setup — documented in Task 2, not automated):**
- Change Plesk document root from `/httpdocs` to `/httpdocs/public`
- Add GitHub repository to Plesk Git extension, branch `prod`, deploy path `/httpdocs/`
- Copy Plesk webhook URL → paste into GitHub repo Settings → Webhooks

Output: `.github/workflows/deploy.yml`

Create the directory `.github/workflows/` and write the deploy workflow.

The workflow must do exactly the following:

```yaml
name: Deploy to ULPGC

on:
  push:
    branches: [main]

concurrency:
  group: production-deploy
  cancel-in-progress: true

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: write   # required for JamesIves to push to prod branch

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '22'   # package.json requires >=22.12.0
          cache: 'npm'

      - run: npm ci

      - run: npm run build

      - name: Prepare deployment structure
        run: |
          mkdir -p deploy-staging/public
          cp -r dist/. deploy-staging/public/
          printf 'RedirectMatch 404 /\\.git\n' > deploy-staging/.htaccess

      - name: Push to prod branch
        uses: JamesIves/github-pages-deploy-action@v4
        with:
          branch: prod
          folder: deploy-staging
          clean: true
          commit-message: "deploy: ${{ github.sha }}"
```

Add a comment block at the top of the file explaining:
- The prod branch is a deployment-only branch (force-pushed by CI — never edit manually)
- The three-step deploy: build → stage → push to prod
- Plesk Git extension polls/webhooks prod and copies to /httpdocs/
- `permissions: contents: write` is required for the push step (GITHUB_TOKEN needs write access)

Do NOT add any server credentials, FTP settings, or IP addresses to this file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub → prod branch | CI pushes built files; GITHUB_TOKEN scoped to repo write only |
| prod branch → ULPGC server | Plesk pulls over HTTPS (git clone); no credentials leave the server |
| Plesk webhook → GitHub | Webhook URL is obscurity-based; no secret payload needed for git pull |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01-01 | Information Disclosure | .git/ directory in /httpdocs/ | mitigate | Document root is /httpdocs/public/ (not /httpdocs/); .htaccess also denies /.git/ access |
| T-04-01-02 | Elevation of Privilege | Fork PR triggers push to prod | mitigate | `on: push: branches: [main]` — only commits merged to main trigger the workflow |
| T-04-01-03 | Tampering | Concurrent deploys race condition | mitigate | `concurrency: production-deploy, cancel-in-progress: true` |
| T-04-01-04 | Tampering | prod branch manually edited | accept | prod is force-pushed by CI on every main push — manual edits are overwritten |
| T-04-01-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages; JamesIves action is a GitHub Action tag reference |
</threat_model>
