<task type="auto">
  <name>Task 1: Contrast audit and fix for --color-accent link color</name>
  <files>src/styles/global.css</files>
  <action>
The research identified that `--color-accent: #52b788` on white (`#ffffff`) has an approximate contrast ratio of 3.14:1, which fails WCAG AA 4.5:1 for normal-size link text. This must be verified and fixed before shipping.

**Step 1 — Verify the contrast ratio:**
Use the WebAIM contrast checker at https://webaim.org/resources/contrastchecker/ to check `#52b788` (foreground) against `#ffffff` (background).

- If ratio >= 4.5:1: no change needed; document the actual ratio in the SUMMARY.
- If ratio < 4.5:1 (expected): proceed to Step 2.

**Step 2 — Find and update the CSS Custom Property:**
Read `src/styles/global.css`. Find the `--color-accent` declaration. Update it to a darker green that achieves >= 4.5:1 on white.

Recommended replacement: `#2a7a5c` — estimated ~5.5:1 on white. Verify this value also achieves >= 4.5:1 before committing by checking https://webaim.org/resources/contrastchecker/?fcolor=2a7a5c&bcolor=ffffff.

If `#2a7a5c` achieves >= 4.5:1, update the `--color-accent` value in global.css. Do not change any other property or add new rules.

**Step 3 — Verify accent color is used consistently:**
The accent color may appear in multiple places:
- `--color-accent` CSS Custom Property declaration in `:root {}` (global.css)
- `.content-page :global(a) { color: var(--color-accent) }` in ContentPage.astro
- `.toc a { color: var(--color-accent) }` in TableOfContents.astro

Since all usages reference `var(--color-accent)`, updating the `:root` declaration is sufficient — no other file changes needed.

**Step 4 — Rebuild and visually confirm:**
Run `npm run build && npm run preview`. Navigate to any content page (e.g., http://localhost:4321/micologia/generalidades/) and visually confirm that links still look green and are legible. The slightly darker green should be visually acceptable — it is a professional shade of green, not a drastic change.
