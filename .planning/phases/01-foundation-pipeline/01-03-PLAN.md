**As a** solo developer about to migrate 14 FrontPage ISO-8859-1 content files, **I want to** have a validated repeatable extraction script that converts one .htm file to clean UTF-8 Markdown (stripping webbot/mstheme artifacts and decoding entities), **so that** Phase 2 can batch-process all 14 content sections without encoding surprises.

Purpose: Prove the extraction tooling works end-to-end on a representative fixture BEFORE Phase 2 relies on it across 14 real files. The script and verifier commit together with their reference fixture so regressions in Phase 2 are catchable by re-running the fixture test.

Output: scripts/extract_frontpage.py + scripts/verify_utf8.py + scripts/requirements.txt + scripts/README.md + a fixture pair + a shell test proving the pipeline is deterministic.

Verified Python package versions from 01-RESEARCH.md Standard Stack:
  - beautifulsoup4 >= 4.15.0
  - markdownify >= 1.2.3
  - html.unescape - stdlib, no install

Pipeline order (01-RESEARCH.md Pattern 6, load-bearing - WebBot regex MUST run BEFORE BeautifulSoup parse):
  1. Read bytes, decode ISO-8859-1
  2. Regex-strip webbot, mstheme, mstable comments and class="_msstyle..." attributes BEFORE parsing
  3. BeautifulSoup parse with html.parser
  4. Strip remaining Comment nodes
  5. Decompose script, style, font, frameset, frame tags
  6. Extract body content, html.unescape() entities (ntilde, nbsp, etc.)
  7. markdownify with heading_style='ATX', bullets='-'
  8. Replace U+00A0 (non-breaking space) with regular space, collapse 3+ blank lines
  9. Write UTF-8 output

CRITICAL encoding verification note (01-RESEARCH.md Pitfall 2, Open Question 4):
  The ROADMAP's byte-range grep (chars 0x80 through 0xFF) success criterion is wrong for Spanish - valid UTF-8 bytes for n-tilde are 0xc3 0xb1 and both are in that range.
  Correct verification: open(path, encoding='utf-8', errors='strict').read() under Python - a UnicodeDecodeError means real corruption, success means clean UTF-8.
