## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| dev machine → ULPGC server over SSH/SFTP | Credentialled transfer; credentials MUST stay off the repo |
| ULPGC server → public internet (HTTPS) | Static content served; HTTPS assumed per 01-RESEARCH.md Assumption A3 — confirmed in Task 1 |
| webmaster communication channel | Out-of-band; answers recorded in `DEPLOY-NOTES.md` (public repo) — must contain no credentials, only non-sensitive config |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | SSH credentials | mitigate | Credentials live only in developer env vars, never in the repo. `scripts/deploy-to-ulpgc.sh` reads env vars; `DEPLOY-NOTES.md` records `${ULPGC_SSH_USER}@…` placeholders only (acceptance criterion enforces this). |
| T-02-02 | Tampering | File permissions on uploaded files | mitigate | rsync invoked with `--chmod=D755,F644` so uploaded files are not world-writable even if the server has lenient defaults. |
| T-02-03 | Spoofing | Live URL identity | mitigate | Verify-live script asserts HTTPS by requiring `https://` scheme (unless webmaster confirmed HTTP-only in Task 1) and relies on the system CA bundle for TLS verification (`fetch` default). |
| T-02-04 | Information Disclosure | HTTPS enforcement | mitigate | If webmaster confirms HTTPS is NOT enforced, Task 1 output must document that gap and the plan surfaces it as a Phase 4 (Launch) follow-up — static scaffolding does not block on this. |
| T-02-05 | Denial of Service | ULPGC server availability | accept | Static files, university infrastructure; outside Phase 1 control. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | This plan installs no new packages; it uses existing Plan 01 toolchain plus system `rsync` and Node's built-in `fetch`. No `[ASSUMED]`/`[SUS]`/`[SLOP]` surface area. |
</threat_model>
